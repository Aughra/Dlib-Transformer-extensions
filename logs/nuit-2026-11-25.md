### Chantier 3 — Markdown → HTML côté serveur (à faire)

Deux voies possibles :
1. Un petit parseur Markdown en C++ écrit maison, inspiré de GFM, avec un ensemble réduit mais couvrant (gras, italique, listes, code, tableaux, liens, images, titres, HTML inline nettoyé).
2. Embarquer une bibliothèque C++ existante (md4c, cmark-gfm). Choix facile côté licence (MIT / CC0).

Choix à poser : maison (pour l'indépendance, règle du fork) ou bibliothèque (pour la fiabilité et le temps). Je décide au début du chantier.

Difficulté connue : le streaming. Le serveur reçoit des tokens au fil de l'eau ; rendre du HTML sûr d'un markdown incomplet demande soit d'attendre les fins de bloc, soit de laisser les listes et les blocs ouverts (et de fermer côté client au dernier fragment).

### Chantier 4 — Coloration du code maison (Gulliver 7.3.5, session « Gulliver »)

- **Partage** : convenu par messages avec la session voisine (elle : `i18n.js` puis le découpage de `service.js` ; « Gulliver » : la coloration). Le Markdown côté serveur reste à discuter à deux avant d'être pris (couture avec DOMPurify et le flux).
- **Un découpeur par fiche de langage, pas un analyseur** : mots-clés, types, littéraux, fonctions connues, commentaires, chaînes, nombres, noms après `def`/`fn`/`class`… ; découpeurs à part pour HTML/XML, CSS, JSON, YAML et diff. Raison : c'est ce que fait highlight.js, à bien moindre coût ; 22 langages couvrent ce que les modèles écrivent dans un chat.
- **Mêmes classes `hljs-*`** : les thèmes GitHub clair et sombre de la page (et la bascule de `preferences.js`) restent ; seul `highlight.min.js` part.
- **Deviner le langage** : signes forts (`#include`, `def …:`, `fn`+`let`, `SELECT…FROM`, `{"clé":`…) puis mots-clés en appoint ; sous un score de 5, pas de couleur (« du texte brut vaut mieux qu'une couleur fausse »). Comme avant, seulement une fois la réponse écrite et sous 20 000 caractères.
- **Côté page, sans clignoter** : un bloc s'affiche d'abord en texte simple, marqué `data-hl` ; les blocs d'un passage partent en une requête ; les 400 derniers HTML reçus sont gardés, et un bloc déjà coloré se redessine aussitôt (la réponse en flux redessine son dernier bloc dix fois par seconde).
- **Sécurité** : le service échappe tout et n'écrit que des `<span class>` ; la page repasse quand même le HTML par DOMPurify réduit à `span` et `class`. Vérifié sur 77 475 colorations (fichiers du dépôt et textes au hasard, dans chaque langage) : texte d'origine retrouvé à l'identique, aucune autre balise.
- **Version 7.3.5 (correctif)** : la coloration existait, elle change de place ; la route est nouvelle mais sert la même fonction.
